## 1. 한 줄 요약

인프런 작심삼일 챌린지를 진행하며 공부 시간 인증에 사용할 스톱워치

## 2. 왜 만드는가

- **지금은 이렇게 한다**: 다른 사람이 만든 스톱워치나 OS 기본 스톱워치를 사용한다.
- **뭐가 불편한가**: UI가 불편하거나 내가 원하는 기능을 추가하지 못해 아쉽다.

## 3. 비목표

- NG-1. **계정·로그인을 만들지 않는다.** 혼자 쓰고, Tailscale 안에서만 접근된다. 닉네임은 화면 표시용 문자열일 뿐 인증 수단이 아니다.
- NG-2. **공개 인터넷에 배포하지 않는다.** 사설망 접근만 상정한다. 접근 제어·레이트리밋·CORS 화이트리스트 같은 것을 만들지 않는다.
- NG-3. **여러 사람이 동시에 쓰는 것을 상정하지 않는다.** 데이터는 단일 사용자 기준이고, 동시 편집·충돌 해소를 다루지 않는다.
- NG-4. **주/월 통계 대시보드를 만들지 않는다.** 집계 화면은 FR-8 달력 하나로 끝낸다.
- NG-5. **모바일 네이티브 앱을 만들지 않는다.** 폰에서도 브라우저로 접속한다.
- NG-6. **Chrome·Edge 외 브라우저를 지원하지 않는다.** FR-3이 Document Picture-in-Picture API에 의존한다.
- NG-7. **인프런 사이트와 연동하지 않는다.** 강의명·강사명은 손으로 적는 문자열이다. 크롤링·API 연동을 하지 않는다.

## 4. 기능 요구사항

**9개 전부 만든다.** 아래 우선순위는 범위를 줄이는 것이 아니라 **만드는 순서**다. 1단계가 끝나면 2단계, 그다음 3단계로 이어서 채운다.

| ID | 기능 | 순서 | 수용 기준 |
|---|---|---|---|
| FR-1 | 스톱워치 | 1단계 | 시/분/초/밀리초 가 모두 보이는 스톱워치 |
| FR-6 | 날짜 표출 | 1단계 | 오늘의 연/월/일/요일 표출 |
| FR-7 | 닉네임 설정 | 1단계 | 닉네임을 설정해 스톱워치를 사용 중인 사용자가 누구인지 보여주는 기능 |
| FR-9 | 강의 정보 표출 | 1단계 | 강의명·강사명을 설정해 화면에 함께 표시 |
| FR-2 | 스크린샷 | 2단계 | 브라우저에서 보이는 스톱워치의 화면을 클립보드 복사·서버 보관 |
| FR-5 | 알람 또는 알림 | 2단계 | 목표 시간 달성 시 단발 알림 + 지정 간격 반복 알림, 소리 포함 |
| FR-3 | PIP | 3단계 | 스톱워치를 PIP 모드로 전환하여 화면에 띄울 수 있는 기능 |
| FR-4 | 배경 설정 | 3단계 | 이미지를 첨부하면 스톱워치 배경으로 설정 가능 |
| FR-8 | 달력 기능 | 3단계 | github streak 처럼 달력 위에 각 일별로 몇 분의 스톱워치를 실행했는지 표시 |

- **다크·라이트 두 테마를 지원한다**: 기본은 다크다 — 계속 켜두고 PIP 로 띄우는 화면이라 눈이 편한 쪽이 기본이라야 한다. 선택은 설정에 저장해 기기 간에 따라간다. 캔버스는 CSS 변수를 못 읽으므로 팔레트를 따로 두고 `styles.css` 의 토큰과 짝을 맞춘다. 배경 이미지 위에 덮는 막도 테마마다 뒤집힌다 — 다크는 어둡게, 라이트는 밝게 덮어야 글자가 읽힌다.
- **화면은 셋으로 나눈다**: 스톱워치 / 기록 / 설정. 스톱워치 화면이 이미 이번 달 달력과 연속 일수를 품고 있어서, 공부하는 동안에는 나머지가 필요 없다. 한 페이지에 다 쌓으면 정작 주인공인 시계가 화면의 절반만 차지한다. 라우터는 붙이지 않고 해시로 나눈다 — 뒤로가기와 북마크가 되는 것으로 충분하다.
- **1단계를 먼저 하는 이유**: FR-1·6·7·9가 곧 인증 스크린샷 한 장에 들어가야 할 내용(누가 · 무슨 강의를 · 언제 · 얼마나)이다. 이게 되면 나머지가 없어도 인증 자체는 된다.

### 4.1 FR-1 스톱워치

- **하는 일**: 시작·일시정지·재개·기록·버리기. 화면에 `HH:MM:SS.mmm`을 표시한다. 일시정지 구간은 학습 시간에서 제외한다.
- **버튼 이름은 "기록"이지 "정지"가 아니다**: 누르면 이번 세션이 기록으로 남고 시계는 0으로 돌아간다. "정지"라고 적으면 일시정지처럼 읽히는데 실제로는 되돌릴 수 없는 확정이라 오해가 위험하다.
- **기록과 버리기는 다르다**: 기록은 남기고 끝낸다. 버리기는 이번 세션을 남기지 않고 지운다 — 켜둔 채 자리를 비웠을 때 쓴다. 되돌릴 수 없으므로 한 번 더 묻는다.
- **어떻게**: 경과 시간은 서버가 소유한다. 클라이언트는 `시작 시각`과 `일시정지 구간`을 받아 그 기준으로 화면만 그린다. `setInterval` 호출 횟수를 세지 않는다 — 백그라운드 탭에서 브라우저가 타이머를 늦춰도 시간이 밀리지 않게.
- **실패하면**: 서버가 안 뜨면 화면에 "연결 끊김"을 띄우고 시작 버튼을 막는다. 이미 돌아가던 세션은 클라이언트가 마지막으로 받은 시작 시각 기준으로 계속 그리되, 그 시간을 기록으로 인정하지 않는다.

### 4.2 FR-2 스크린샷

- **하는 일**: 현재 화면(배경 이미지·시간·날짜·닉네임·강의 정보 포함)을 PNG로 만들어 ① 클립보드 복사 ② 서버 보관, 두 가지를 한다. 파일명에 날짜·시각을 넣는다.
- **어떻게**: 스톱워치 표시부를 `<canvas>`로 그린다. 그러면 스크린샷이 `canvas.toBlob()` 한 줄이고 html2canvas 같은 의존성이 필요 없다. 같은 캔버스를 FR-3 PIP에서 재사용한다.
- **내보낼 때는 1200x675 로 고정한다**: 표시용 캔버스는 화면 밀도만큼 커서 폰(dpr 3)에서는 3600x2025 이 된다. 그대로 두면 장당 몇 MB 씩 쌓인다. 기기와 무관하게 같은 크기로 줄여 파일 크기를 예측 가능하게 둔다 (장당 약 740KB).
- **서버에는 최근 50장만 남긴다**: 넘으면 오래된 것부터 파일과 행을 함께 지운다. 최대 약 36MB. 목록에만 있고 파일이 없는 상태가 생기지 않게 둘을 같이 지우는 것이 중요하다.
- **자동으로 내려받지 않는다**: 한 장 찍을 때마다 다운로드 폴더가 지저분해진다. 찍은 것은 서버에 쌓아 두고, 파일이 필요하면 달력에서 그 장을 골라 직접 내려받는다.
- **실패하면**: 클립보드 쓰기가 거부되면(권한 거부 등) 화면에 이유를 알린다. 서버 보관은 그대로 진행하므로 달력에서 다시 꺼낼 수 있다.

### 4.3 FR-3 PIP

- **하는 일**: 스톱워치를 항상 위에 뜨는 작은 창으로 분리한다. PIP 창 안에서도 시작·일시정지를 누를 수 있어야 한다.
- **어떻게**: Document Picture-in-Picture API. 캔버스를 video로 흘려보내는 방식은 PIP 창이 보기 전용이 되므로 쓰지 않는다.
- **그리기는 그 창의 `requestAnimationFrame`으로 돈다**: 본 창이 뒤로 가면 본 창의 rAF 는 멈춘다. PIP 를 쓰는 상황이 정확히 그 상황이므로, 캔버스가 어느 문서에 있는지에서 창을 유도해 그 창의 rAF 를 쓴다.
- **스타일시트는 새 창으로 따라가지 않는다**: 통째로 복제해 넣는다.
- **실패하면**: API가 없는 브라우저면 PIP 버튼을 아예 숨긴다. 버튼은 있는데 창이 안 열리는 경우(브라우저가 막거나 창을 못 만드는 경우)에는 이유를 화면에 적는다 — 조용히 삼키면 눌러도 아무 일도 안 일어나는 것처럼 보인다.

### 4.4 FR-4 배경 설정

- **하는 일**: 이미지를 업로드해 스톱워치 배경으로 쓴다. 서버에 보관하므로 PC에서 올린 배경이 폰에서도 보인다. 여러 장 올려두고 골라 쓸 수 있다.
- **받는 형식**: PNG · JPEG · WebP, 장당 8MB, 최대 20장. 비율을 지키며 화면을 꽉 채우고 넘치는 쪽은 자른다.
- **어떤 사진을 올려도 시간이 읽혀야 한다**: 이미지 위에 어두운 막을 덮고, 글자에는 그림자를 넣는다. 막만 더 진하게 하면 사진이 죽고, 그림자만 넣으면 밝은 사진에서 흐린 색 글자가 묻힌다. 둘 다 필요하다.
- **쓰던 배경을 지우면 설정도 함께 비운다**: 없는 배경을 가리키고 있는 상태가 생기면 안 된다.
- **실패하면**: 용량·형식 제한을 넘으면 막고 이유를 알린다. 배경 파일이 없어지면 기본 배경으로 떨어진다 — 배경 때문에 스톱워치가 안 보이는 일은 없게 한다.

### 4.5 FR-5 알람 또는 알림

- **하는 일**: ① 목표 시간 도달 시 단발 알림 ② 지정 간격마다 반복 알림. 둘 다 소리를 함께 낸다.
- **기본값은 없다**: 목표 시간도 반복 간격도 처음엔 비어 있고, 알림은 꺼진 상태다. 값을 직접 넣으면 그때부터 동작한다. 25분·2시간 같은 값을 미리 넣어두지 않는다.
- **어떻게**: Notification API + 오디오 재생. secure context가 필요하므로 PC는 `localhost`, 폰은 Tailscale HTTPS로 접속한다. 소리는 짧은 두 음을 그때그때 합성한다 — 음원 파일을 레포에 두지 않기 위해서다.
- **매 프레임 검사하지 않고 다음 울릴 시각을 예약한다**: 백그라운드 탭에서는 `requestAnimationFrame`이 멈춘다. 공부하는 동안 탭이 뒤에 있는 것이 정상이므로, 검사 방식으로는 알림이 오지 않는다. 예약해 둔 타이머는 그래도 깨어난다.
- **무엇이 울렸는지 기억하지 않는다**: 항상 "지금 경과 시간 다음"을 계산한다. 그래서 새로고침하거나 다른 기기에서 열어도 이미 지난 알림이 다시 울리지 않는다.
- **실패하면**: 알림 권한이 거부되면 화면 안 배너와 소리로 대체한다. 알림이 안 떴다고 스톱워치가 멈추지는 않는다.

### 4.6 FR-6 날짜 · FR-7 닉네임 · FR-9 강의 정보

- **하는 일**: 오늘의 연/월/일/요일, 닉네임, 강의명·강사명을 스톱워치와 같은 캔버스에 그린다. 인증 스크린샷 한 장에 "누가 · 무슨 강의를 · 언제 · 얼마나"가 모두 담기게 하는 것이 목적이다.
- **강의 정보는 손으로 적는다**: 강의명·강사명 두 개의 자유 입력 필드다. 인프런에서 긁어오지 않는다(NG-7). 마지막에 넣은 값이 유지되므로 같은 강의를 듣는 동안 다시 칠 일이 없다.
- **실패하면**: 값이 비어 있으면 그 줄을 통째로 비운다. 기본값을 지어내거나 "미설정" 같은 문구를 넣지 않는다 — 인증 스크린샷에 그대로 찍히기 때문이다.

### 4.7 FR-8 달력 기능

- **하는 일**: 날짜별 누적 학습 시간을 GitHub 잔디 형태로 보여준다.
- **학습일은 세션을 시작한 날이다**: 자정을 넘겨도 세션을 쪼개지 않는다. 23:50 에 시작해 01:00 에 끝냈으면 전부 시작한 날에 붙고, 00:30 에 시작했으면 그때는 이미 새 날이므로 그날에 붙는다. `study_date = 시작 시각의 날짜`.
- **대신 이런 경우가 생긴다**: 22시에 시작해 새벽 6시까지 이어간 8시간은 전부 시작한 날 하나에 몰린다. 밤샘이 잦으면 잔디가 한쪽으로 쏠린다. 그때 다시 본다.
- **목표를 잡았으면 시계 아래에 진행 막대를 그린다**: 달성률과 목표 시간을 양 끝에 적는다. 목표를 안 잡았으면 막대도 라벨도 그리지 않는다 — 왼쪽이 비어 보인다고 없는 값을 지어내지 않는다.
- **표시면에 이모지를 쓰지 않는다**: 이모지는 기기마다 다른 그림으로 그려진다. 인증 스크린샷에 찍히는 것이므로 강조는 색과 크기로만 한다.
- **달력은 스톱워치 화면 안에 있다**: 인증 스크린샷 한 장에 "이번 달을 얼마나 이어왔는지"까지 담기게 하는 것이 목적이다. 그래서 표시면을 1600x900 으로 키우고 왼쪽은 시계, 오른쪽은 이번 달 달력과 연속 일수로 나눴다.
- **한 번에 한 달만 본다**: 반년치 잔디는 칸이 너무 작아 며칠을 했는지 읽히지 않는다. 월 격자는 항상 6주 고정이다 — 달마다 주 수가 바뀌면 화면 높이가 들썩인다.
- **색 단계**: 30분 / 1시간 / 2시간을 경계로 4단계. 기록이 없으면 빈 칸.
- **연속 일수는 스톱워치 화면에 크게 둔다**: 작심삼일 챌린지가 연속으로 하는 것이 목적이기 때문이다. 오늘 아직 시작 전이면 어제까지의 연속을 보여준다 — 하루가 끝나기도 전에 0이 되면 맥이 빠진다.
- **달력 화면에서 날짜를 누르면 그날의 기록 목록과 스크린샷을 함께 본다**: 몇 시부터 몇 시까지 얼마나 했는지 한 건씩 보이고, 잘못 남은 기록은 지울 수 있다. 되돌릴 수 없으므로 한 번 더 묻는다.
- **돌고 있는 기록은 목록에서 지우지 못한다**: 그건 버리기가 할 일이다. 같은 일을 하는 버튼이 둘이면 헷갈린다.
- **집계는 부팅할 때 원본에서 다시 만든다**: `daily_study` 는 파생 데이터라 언제든 재현될 수 있어야 한다. 기록을 지웠거나 집계가 어긋나도 서버를 다시 띄우면 맞춰진다.
- **실패하면**: 집계 테이블이 비어 있으면 빈 달력을 보여준다. 세션 원본이 남아 있으므로 언제든 재집계할 수 있어야 한다. 달력을 못 불러와도 스톱워치는 계속 돈다.

## 5. 기술

### 5.1 스택과 고른 이유

| 영역 | 선택 | 고른 이유 |
|---|---|---|
| 언어 · 런타임 | TypeScript / Node.js | 프론트와 백엔드가 같은 언어·같은 타입 정의를 공유한다. 레포 하나로 끝난다. |
| 프론트엔드 | React + Vite | 스톱워치 상태·설정·기록 세 덩어리를 다루기에 적당하다. 정적 빌드라 서빙이 단순하다. |
| 백엔드 | Hono | 엔드포인트가 10개 안쪽이다. 정적 파일 서빙과 API를 한 프로세스에서 처리해 컨테이너를 하나로 유지한다. |
| 저장소 | SQLite (better-sqlite3) | 단일 사용자, 동시 쓰기 없음. 파일 하나라 백업이 복사 한 번이다. |
| 돌아가는 곳 | 집 PC의 docker-compose | 컨테이너 1개 + 볼륨 1개(SQLite 파일 + 업로드 이미지). 폰에서는 Tailscale로 접속한다. |
| 렌더링 | `<canvas>` | FR-2 스크린샷과 FR-3 PIP가 같은 그리기 코드를 공유한다. 스크린샷에 별도 라이브러리가 필요 없다. |
| 폰트 | Pretendard + JetBrains Mono, 직접 싣는다 | 이름만 부르면 안 깔린 기기에서 조용히 `system-ui` 로 떨어져 인증 스크린샷이 기기마다 다른 글자로 찍힌다. 빌드 타임에만 필요하므로 `devDependencies` 에 둔다 — 런타임 이미지가 커지지 않는다. |
| CSS | 손으로 쓴 `styles.css` | Tailwind·Bootstrap 은 캔버스에 닿지 않는다. 표시면이 이 앱의 결과물이므로 프레임워크가 바꿀 수 있는 부분이 거의 없다. 토큰 몇 개로 충분하다. |

### 5.2 데이터

- **경과 시간의 소유자는 서버다.** 클라이언트는 그리기만 한다. 그래야 PC에서 시작한 세션을 폰에서 이어 볼 수 있고, 탭이 갑자기 닫혀도 기록이 남는다.
- 테이블(안):

| 테이블 | 담는 것 |
|---|---|
| `settings` | 닉네임, 강의명, 강사명, 목표 시간, 반복 알림 간격, 소리 on/off, 현재 배경 (단일 행) |
| `session` | 세션 원본 — 시작 시각, 종료 시각, 상태(running/paused/finished) |
| `pause_span` | 일시정지 구간 — 세션별 (paused_at, resumed_at). 학습 시간 계산의 근거 |
| `daily_study` | 세션 시작일 기준으로 집계한 (study_date, total_ms). FR-8 달력이 읽는 곳 |
| `background` | 업로드된 배경 이미지 메타 |
| `screenshot` | 서버에 보관한 스크린샷 메타 |

- `daily_study`는 `session` + `pause_span`에서 언제든 다시 만들어낼 수 있는 파생 데이터로 둔다. 집계가 틀어져도 원본으로 복구할 수 있게.

### 5.3 신경 쓸 것

- **체감 속도**: 밀리초 표시는 `requestAnimationFrame`으로 그린다. 서버 왕복은 시작·정지·주기 저장에만 쓰고, 화면 갱신에는 쓰지 않는다.
- **비밀정보**: 없다. 계정도 외부 API 키도 쓰지 않는다. 업로드된 이미지는 커밋 대상이 아니므로 `.gitignore`에 넣는다.
- **지원 범위**: `docker compose up` 한 번으로 뜬다. 브라우저는 Chrome·Edge. 폰 접속은 Tailscale.
- **비용**: 0원. 집 PC와 Tailscale 무료 요금제로 끝낸다.
